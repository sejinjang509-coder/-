# Re:Balance AI

**AI-powered Policy Portfolio Engine** — 한국 AI·금융 공모전을 위한 80초 인터랙티브 모션그래픽 데모.

신용보증재단중앙회의 재보증·리스크관리 담당자가 지역경제 신호를 파악하고, 정책 목표에 맞는 포트폴리오 대안을 비교하는 흐름을 8개의 장면으로 보여줍니다. AI는 의사결정을 지원하며 **최종 결정은 담당자**가 합니다.

> 모든 뉴스, 신뢰도, 예측, 시나리오 수, 배분, 스트레스 결과는 가상 예시입니다. 실제 LLM·예측·최적화 모델을 실행하거나 자금을 배분하지 않습니다. 외부 API 호출, 계정, 비밀키, 빌드, 패키지 설치가 필요 없습니다.

## 파일

```text
index.html  CSS·JavaScript·SVG를 모두 포함한 단일 파일 데모
styles.css  디자인 토큰, 16:9 화면, 반응형 스타일, 모션
app.js      DEMO_DATA, 장면 문구·렌더링, 상태·타이머·상호작용
README.md   실행·수정·배포 안내
scripts/sync-html.mjs  수정한 CSS·JS를 HTML에 반영하는 선택적 편집 도구
```

## 실행

**`index.html` 하나만 내려받아 Chrome·Edge·Safari 같은 브라우저에서 열면 됩니다.** CSS·JavaScript·SVG를 파일 안에 포함하므로 같은 폴더에 다른 파일이 없어도 동작합니다. 별도 설치나 인터넷 연결 없이 실행할 수 있습니다.

GitHub의 코드 화면에서는 HTML이 실행되지 않습니다. 저장소의 `index.html` 파일 화면에서 **Download raw file**로 내려받아 브라우저로 여세요. 메신저·문서 앱의 미리보기는 JavaScript 실행을 제한할 수 있습니다.

화면에 기본 글자와 버튼만 보이면, 이전 버전 HTML을 단독으로 내려받았거나 CSS·JavaScript 파일을 읽지 못한 상태일 수 있습니다. 최신 단일 파일 `index.html`을 다시 내려받아 브라우저에서 확인하세요.

로컬 HTTP 서버를 사용할 경우 저장소 루트에서:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 서버는 `Ctrl+C`로 종료합니다. 이 주소는 로컬 실행용이며 다른 기기용 QR 링크가 아닙니다.

## 조작

- 자동재생: 8개 장면 × 10초, 총 약 80초. 마지막 장면에서 정지합니다.
- `Space` 또는 `→`: 다음 장면. `←`: 이전 장면.
- 화면 오른쪽 / 왼쪽 클릭·터치: 다음 / 이전 장면.
- 하단 8개 진행 막대: 특정 장면으로 이동.
- 직접 이동하거나 대안·시나리오를 선택하면 자동재생이 멈춥니다. 재생 버튼으로 이어서 볼 수 있습니다.
- `REPLAY` 또는 로고: 처음부터 다시 재생하고 기본 대안·시나리오로 초기화합니다.
- 포트폴리오: 안정형 / 균형형 / 지원확대형을 선택하면 다음 스트레스 장면에 선택한 대안이 반영됩니다. 기본 균형형은 비교용 선택이며 추천이 아닙니다.
- 스트레스 테스트: 금리 / 건설업 / 지역매출을 누르면 양쪽 가용 여력이 부드럽게 바뀝니다.
- 모바일의 **내용 크게 보기**: 현재 장면의 내용을 읽기 쉬운 글씨로 펼칩니다. 펼치면 자동재생이 멈추며, 선택한 대안·충격도 설명에 반영됩니다.
- 키보드 `Tab`으로 컨트롤을 선택하고 `Enter` 또는 `Space`로 실행할 수 있습니다.
- `Tab`으로 컨트롤을 탐색하기 시작해도 자동재생이 멈춥니다.
- 운영체제의 모션 감소 설정을 존중합니다. 해당 설정에서는 자동재생을 기본 정지하고, 이동·숫자 애니메이션을 최소화합니다. 재생 버튼으로 자동재생을 명시적으로 시작할 수 있습니다.
- 다른 탭으로 이동한 동안 자동재생 시간이 진행되지 않습니다.

데스크톱 기준 화면은 1440 × 810의 16:9입니다. 모바일 세로 화면에서도 동일한 비율로 화면 폭에 맞추며, 컨트롤과 안내는 화면 바깥에 유지합니다. 작은 화면에서 보조 글씨가 작아질 경우 **내용 크게 보기**를 펼치거나 가로 화면으로 확인할 수 있습니다.

## 수정

`styles.css`와 `app.js`는 편집용 원본입니다. 수정한 뒤 아래 명령으로 내용을 `index.html`에 반영하고, 갱신된 HTML도 함께 커밋하세요. 이 명령은 **원본을 수정할 때만** 필요하며 데모를 열거나 배포할 때는 필요 없습니다. HTML의 SVG·레이아웃은 직접 수정할 수 있습니다.

```sh
node scripts/sync-html.mjs
node scripts/sync-html.mjs --check
```

- **예시 숫자:** `app.js` 상단 `DEMO_DATA` 한 곳에서 관리합니다. `// DEMO VALUE — replace with real analysis result` 주석을 유지하세요.
- **장면 제목·하단 설명·재생 시간:** `SCENES` 배열에서 수정합니다.
- **장면 오브젝트 문구·배치:** `dilemmaScene`부터 `closingScene`까지 렌더 함수와 대응 CSS를 수정합니다. 장면별 숫자 애니메이션은 `startSceneEffects`에서 연결합니다.
- **디자인:** `styles.css`의 `:root`에 7개 색상과 easing을 정의했습니다. 외부 폰트 없이 시스템의 Pretendard / 한국어 폰트 스택을 사용합니다.
- **공통 SVG:** `index.html`의 `<defs>`에 풀·문서·기관·체크 등을 정의했습니다.
- **상태:** `state`의 장면 인덱스·재생 여부·선택 대안·스트레스 시나리오를 사용합니다. 전환 시 이전 타이머·숫자 애니메이션을 취소하고, 이전 장면을 `inert` 처리한 뒤 800ms 교차 전환 후 제거합니다.

실제 분석 데이터를 연결할 경우 단위, 모델 검증, 데이터 시점, 정책 제약, 담당자 승인 절차를 먼저 정의해야 합니다. 숫자만 바꾸고 실제 결과인 것처럼 표시하지 마세요.

## 배포 및 QR

커밋·푸시는 파일을 GitHub에 저장합니다. **웹사이트 공개는 별도 배포 작업**입니다.

### GitHub Pages

1. GitHub 저장소 **Settings → Pages**를 엽니다.
2. **Deploy from a branch**를 선택합니다.
3. `main` 브랜치와 `/ (root)`를 선택하고 저장합니다.
4. 배포가 완료되면 Pages에서 제공하는 HTTPS 주소를 사용합니다.

모든 경로는 상대 경로여서 저장소 하위 경로에서도 동작합니다. GitHub 요금제와 저장소 공개 범위에 따라 Pages 사용 가능 여부와 사이트 접근 범위가 달라질 수 있습니다. Pages에 표시되는 실제 공개 범위를 확인하세요.

### Vercel / Netlify

- GitHub 저장소를 가져옵니다.
- 프레임워크는 **Other / 정적 사이트**, 빌드 명령은 비우고, 게시 디렉터리는 저장소 루트(`.`)로 설정합니다.
- 저장소 루트를 그대로 제공합니다. `index.html`에 실행에 필요한 모든 코드가 포함되어 있습니다.
- 발급된 HTTPS 주소를 다른 기기에서 확인한 뒤 QR 코드에 연결하세요.

QR에는 GitHub 저장소 파일 화면이 아닌 **실제 배포된 사이트 주소**를 넣습니다. 이 데모에는 추적 도구, 외부 글꼴, 원격 이미지, 사용자 정보 수집이 없습니다.

## 확인할 동작

전체 자동재생, 키보드·터치 이동과 일시정지, 빠른 연속 이동, REPLAY 초기화, 세 대안의 스트레스 결과, 세 가지 충격 선택, 모바일 세로·가로 화면, 모션 감소 설정을 확인합니다. 개발자 도구에 JavaScript 오류가 없어야 하며, 8개 장면에서 가상 시뮬레이션 표시가 유지되어야 합니다.

제작 시 Chromium에서 80초 전체 재생, 수동 정지·재시작, 숫자 결과, 포트폴리오·충격 선택, 포커스 유지, 320 / 390 / 600 / 844 / 1440px 화면 배치, 모션 감소와 오프라인 소스 실행을 확인했습니다. 단일 파일 버전은 CSS·JS 원본을 제공하지 않는 서버와 네트워크가 없는 브라우저에서도 8개 장면과 스트레스 선택을 확인했습니다. 클라우드 Chromium의 관리 정책이 `file://` 탐색을 차단하므로 직접 파일 열기의 자동 검증은 수행하지 못했고, HTML 파일 하나만 제공하는 HTTP 실행 및 동일 파일의 오프라인 실행을 검증했습니다. 앱은 로컬 파일 실행을 제한하는 API나 외부 의존성을 사용하지 않습니다.
